# Phase 06 - Provider Backends and Account-Login Auth

Canonical spec: `docs/superpowers/specs/2026-05-04-kb-librarian-agent-first-design.md`

## Goal

Expand provider support beyond the current API-key-only adapters by prioritizing broader local-provider backends first, then adding explicit vendor-CLI-backed account auth for Anthropic and Codex routes.

Phase 6 assumes Phases 1-5 are complete.

## Milestone Order

1. [06a - Provider Backend and Credential Source Seams](06a-provider-backend-and-credential-source-seams.md)
   - Priority: establish minimal abstractions so new backends and non-API-key auth do not become one-off hacks.
2. [06b - Additional Local Provider Backends](06b-additional-local-provider-backends.md)
   - Priority: broaden local-first operation before adding new cloud-account auth paths.
3. [06c - Anthropic Account-Login Auth](06c-anthropic-account-login-auth.md)
   - Priority: support Claude Code CLI delegation after the credential-source seam exists.
4. [06d - Codex Account-Login Auth](06d-codex-account-login-auth.md)
   - Priority: support Codex CLI delegation after the same seam is proven on Anthropic.
5. [06e - Auth Policy, Doctor, and Security Polish](06e-auth-policy-doctor-and-security-polish.md)
   - Priority: unify auth precedence, diagnostics, secret handling, and docs after all new auth modes exist.

Each milestone should leave the CLI runnable and preserve existing Phase 5 behavior unless the user explicitly opts into a new backend or credential source.

## Phase Deliverables

- Provider config support for multiple local backends instead of Ollama-only validation.
- First-class local support for `vllm` and `lm_studio`, plus a reusable seam for OpenAI-compatible local servers.
- Credential-source selection that can use API keys or explicit vendor CLI delegation.
- Opt-in Anthropic account routing through Claude Code CLI (`claude -p`) using Claude Code's supported login state or `CLAUDE_CODE_OAUTH_TOKEN` generated by `claude setup-token`.
- Opt-in Codex account routing through Codex CLI (`codex exec`) using ChatGPT sign-in from `codex login` or `codex login --device-auth`.
- `kb doctor`, CLI errors, and docs that explain which backend and credential source are active and what to fix when auth fails.
- Secret masking and config/logging guardrails for the added auth modes.

## Target Account-Auth Mechanisms

- Anthropic target: delegate account-backed calls to the installed Claude Code CLI, authenticated with `claude auth login` subscription OAuth or `CLAUDE_CODE_OAUTH_TOKEN` generated by `claude setup-token`. KB Librarian should not parse `~/.claude/.credentials.json`, macOS Keychain entries, or browser cookies.
- Codex target: delegate account-backed calls to the installed Codex CLI, authenticated with `codex login` ChatGPT OAuth or `codex login --device-auth`. KB Librarian should not parse `~/.codex/auth.json`, OS keyring entries, or browser cookies.
- Direct HTTP providers remain API-key based unless a vendor documents a stable bearer-token contract for third-party clients.
- CLI delegation must run in a completion-only posture: no model-initiated shell/file tools, deterministic prompts, structured-output schema where available, bounded timeout, and non-secret diagnostics.

Research basis: Claude Code documents `claude auth login`, `claude auth status`, `claude setup-token`, `CLAUDE_CODE_OAUTH_TOKEN`, and `claude -p`; Codex documents `codex login`, `codex login --device-auth`, cached ChatGPT login, and `codex exec` with `--output-schema`.

## Final Acceptance Criteria

- Users can run provider-backed flows against Ollama, vLLM, and LM Studio through documented config-only changes.
- Existing API-key-based Anthropic and Codex routes continue working unchanged.
- Users can explicitly opt into Claude Code CLI and Codex CLI delegation without storing raw API keys in KB Librarian config.
- Auth selection is deterministic, inspectable, and safe by default.
- `kb doctor` can distinguish missing credentials, expired login state, incompatible local backend configuration, and unsupported combinations.
- Logs, review artifacts, and diagnostics do not leak bearer tokens, cookies, or other sensitive auth material.

## Phase Test Strategy

- Unit tests for config validation, backend selection, credential-source precedence, and secret masking.
- Provider tests for Ollama, vLLM, LM Studio, Claude Code CLI delegation, and Codex CLI delegation adapters.
- CLI smoke tests that switch routes across supported local and cloud-auth modes using temporary configs.
- Doctor tests that verify targeted findings for missing API keys, missing login state, expired login state, unreachable local backends, and unsupported backend/auth combinations.
- Manual acceptance using real local servers and opt-in live auth checks guarded behind explicit environment flags.

## Out of Scope

- Automatic browser automation, cookie scraping, or direct parsing of vendor credential-cache files.
- Embedded OAuth web servers unless required by a provider-supported device or CLI flow.
- Team/shared multi-user credential storage.
- New retrieval architectures unrelated to provider expansion.
- MCP wrapper work, TUI/web review surfaces, and full embedding retrieval.
